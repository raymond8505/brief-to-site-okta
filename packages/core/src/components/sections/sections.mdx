# Section suite

A **section** is one full-width horizontal band of a page — a hero, a feature grid, a closing call
to action. Sections are the largest composable unit: a page is a stack of them, and each one's slots
are filled with **blocks** (see **Blocks/Overview**).

Browse the suite in the **Sections/\*** tree — each entry documents its own slots, layout axes and
tokens. Import them from `@brief-to-site/core/sections`.

```tsx
import { Hero, HeroBody, HeroMedia } from "@brief-to-site/core/sections";
```

## Sections are full-bleed, with a shared `density`

Every section renders through a full-bleed `<section>` that supplies the standard centred container
(`max-w-7xl`, responsive gutters). Because the shell is full-bleed, a section can carry a background
edge to edge while its content still lands on the shared column — so you never need a wrapper to
make a band span the viewport.

The one axis every section shares is spacing **`density`** (`compact` / `comfortable` / `spacious`).
Reach for it to tighten or open a page's rhythm without touching the sections themselves.

## A variant is a composition

A section is a compound family: a root plus **named slot subcomponents** — `Hero` + `HeroBody` /
`HeroMedia` / `HeroAside`, much like the `Card` family. You fill those slots with blocks; **never
ad-hoc markup**.

That is what makes a variant a *composition* rather than a flag. The same `Hero` reads as split,
centered, with-stats or quote-led purely by which blocks fill which slots — so when you want a
different look, change the composition before you look for a prop. Any genuine geometry a section
does own (which side the media sits on, how many columns) is a small layout prop, and layout can
react to which slots you filled.

A dev-only guard warns in the console when a component lands in a slot that doesn't expect it. It's
a safety net for composition mistakes, and it never runs in a built site.

## Filling slots

Slots take **blocks** — the ones published in `@brief-to-site/core/blocks` are simply the blocks
that already exist. A block you author to the same contract is an equally valid slot filler, so a
section is never limited to core's inventory. **Blocks/Overview** covers the block contract and when
to author one.

If no section in the suite provides the band a page needs, compose the arrangement you need rather
than stretching a section to stand in for it. The suite is purpose-built rather than exhaustive, so
"no core section fits this" is an ordinary outcome, not a shortfall.

## Colour

Sections consume **role tokens** — never hardcoded colours — so the deterministic theme stays
orthogonal. Most sections set no colour at all and simply inherit the page surface, taking their
colour from the blocks in their slots; each section's story documents exactly what it consumes. See
**Colors/Overview** for the token system.
