# Colour system

The microsite theme is driven by **one required brand colour** (the primary). Everything else is
**deterministic** — no randomness, no LLM. Two independent mechanisms:

## 1. HSL palette derivation

A single seed (`--brand-h` / `--brand-s` / `--brand-l`, unitless HSL channels) produces the palette
via fixed HSL transforms. The same constants live in [`palette.ts`](?path=/story/colors-palette--default)
(`HUE_OFFSETS`, `NEUTRAL_TINT`) so tooling (`theme:build`) and the CSS never drift.

Secondary/tertiary use a **named colour harmony** (default **complementary**). Switch it by pointing
`--secondary-h-offset` / `--tertiary-h-offset` at another pair, e.g. `var(--secondary-h--triadic)`:

| Harmony | secondary offset | tertiary offset |
| --- | --- | --- |
| complementary *(default)* | +150° | +210° |
| triadic | +120° | +240° |
| analogous | +330° (−30°) | +30° |

| Token | Derivation |
| --- | --- |
| `--brand-primary` | the seed |
| `--brand-secondary` | primary hue + active secondary offset |
| `--brand-tertiary` | primary hue + active tertiary offset |
| `--brand-surface` | primary hue, lightness **96%** (brand-tinted near-white) |
| `--brand-muted` | primary hue, lightness **90%** |

Supply an explicit 2nd/3rd colour by overriding `--brand-secondary-*` / `--brand-tertiary-*`.

## 2. WCAG 4.5:1 contrast

The `.wcag-contrast` utility (ported verbatim from
[raymond8505/pure-css-wcag-compliant-dynamic-colors](https://github.com/raymond8505/pure-css-wcag-compliant-dynamic-colors))
takes a background as `--r` / `--g` / `--b` and applies a guaranteed-legible text colour using pure
CSS `pow()`. Chromium (the capture engine) supports it. See the **Contrast** story.

## Role assignment — operator-controlled

Brand tokens are **not** force-assigned to shadcn role vars. core wires only `--primary` and
`--ring` to `--brand-primary`; the operator/agent decides what else uses which colour by pointing
role vars at brand tokens in a site's `theme.css` (see `theme.example.css`). This is why "role
mapping" is a per-site override, not a baked-in rule — it keeps colour assignment a deliberate,
brief-driven choice.

Explore live: **Colors/Palette** (derivation, with seed controls), **Colors/Palette → RoleMapping**
(remapping), **Colors/Contrast** (legible text on any background).
